# 0002. 매니페스트 기록 결함 — 오염된 기록의 표시와 수정

- 날짜: 2026-08-01
- 상태: 채택
- 관련: [0001 규범과 지식의 분리](0001-규범과-지식의-분리.md), 판례 [case-002](../precedents/case-002.md)

## 맥락

`run_regression.py --repeat 5`(실행 5회)를 돌린 뒤 `manifests/`에 신규 매니페스트가 **9건** 생겼다. 실행 횟수와 기록 건수가 맞지 않았고, 그중 1건은 `routing: "incomplete"`였다. 같은 조사에서 `input_hash`가 같은 입력의 회차마다 전부 다르다는 것도 드러났다.

`manifests/`는 append-only이고 통계·규칙 졸업 분석의 원천이다. 개수가 실행 횟수와 맞지 않으면 "N회 이상 만장일치" 같은 집계가 전부 틀어진다.

## 원인

세 현상은 모두 `write_manifest.py`가 **`Stop` 훅 — 즉 "실행 1회 완료"가 아니라 "세션 턴 종료"에 걸려 있고, 완료 여부를 판별하지 않은 채 기록**한 데서 나왔다.

### (A) 중복 기록 3건 — 다른 세션의 훅이 잔여 산출물을 재기록

회귀 하네스는 실행 **시작 시점에만** `runs/current/`를 비우고, 끝난 뒤에는 비우지 않는다. 그래서 배치가 끝난 뒤 사람이 쓰던 대화 세션이 턴을 마칠 때마다 훅이 발동해, 마지막 회차의 잔여 판단 파일을 그대로 다시 기록했다.

증거는 `run_id`의 해시 접미사다. 당시 `run_id`는 `타임스탬프_판정결과해시[:8]` 형식이었으므로, **접미사가 같다는 것은 판정 산출물이 바이트 단위로 동일하다는 뜻**이다.

| 오염된 기록 | 원본 | 접미사 |
|---|---|---|
| [2026-08-01T080048Z_b0c1a5b9](../../manifests/2026-08-01T080048Z_b0c1a5b9.json) | [2026-08-01T075921Z_b0c1a5b9](../../manifests/2026-08-01T075921Z_b0c1a5b9.json) (5회차) | `b0c1a5b9` |
| [2026-08-01T114127Z_b0c1a5b9](../../manifests/2026-08-01T114127Z_b0c1a5b9.json) | 위와 동일 (5회차) | `b0c1a5b9` |
| [2026-08-01T064349Z_096d038c](../../manifests/2026-08-01T064349Z_096d038c.json) | [2026-08-01T062758Z_096d038c](../../manifests/2026-08-01T062758Z_096d038c.json) (배치 이전 실행) | `096d038c` |

### (B) 미완주 기록 1건 — 파이프라인 도중의 턴 종료

[2026-08-01T071854Z_2a27aa26](../../manifests/2026-08-01T071854Z_2a27aa26.json)은 `outputs`에 `analyst`, `independent` 두 역할만 있다. 3회차 세션 도중 analyst·independent가 끝난 시점에 메인 에이전트가 턴을 한 번 종료했고, 훅이 완료 여부를 보지 않고 기록했다. 3회차 자체는 정상 완주해 16:30:18에 5개 역할 전부를 담은 매니페스트를 따로 남겼다. 즉 한 실행이 매니페스트 2건을 만들었다.

### (C) `input_hash`가 실제로는 출력 해시

```python
blob = json.dumps(outputs, ...)          # 판정 결과
"input_hash": "sha256:" + sha256(blob)   # 이름만 input
```

입력이 아니라 **판정 결과**를 해싱하고 있었다. 그래서 같은 입력이라도 판정이 조금만 달라지면 값이 달라졌고, "같은 데이터 → 같은 verdict" 재현성 대조에 쓸 수 없는 필드였다. 이 저장소의 핵심 원칙 2번이 측정 불가 상태였다는 뜻이다.

부수적으로 `escalation_reason` 필드도 실제 사유가 아니라 synthesizer의 `verdict` 문자열(`"needs_review"`)을 기록하고 있었다.

## 결정

### 1. 오염된 기록은 삭제하지 않고 문서로 지목한다

`manifests/`의 append-only 원칙을 지킨다. 위 (A) 3건과 (B) 1건은 **삭제하지 않으며**, 이 문서가 해당 파일들을 링크로 지목하는 것으로 "오염된 기록"임을 표시한다.

이유: 기록을 지우기 시작하면 append-only가 무너지고, "무엇을 지웠는지"를 다시 기록해야 하는 순환에 빠진다. 잘못된 기록도 기록이며, 그것이 왜 잘못됐는지를 덧붙이는 것이 감사 가능한 방식이다.

**집계 시 제외 대상 (총 4건):**
- `manifests/2026-08-01T064349Z_096d038c.json`
- `manifests/2026-08-01T071854Z_2a27aa26.json`
- `manifests/2026-08-01T080048Z_b0c1a5b9.json`
- `manifests/2026-08-01T114127Z_b0c1a5b9.json`

또한 2026-08-01 이전 형식의 모든 매니페스트는 `input_hash` 필드가 (C)의 의미(출력 해시)이므로, **입력 동일성 판정에 사용할 수 없다.** 해당 매니페스트에는 `outputs_hash` 필드가 없다.

### 2. 완료 판별 — `manifests/`는 완주한 실행만 담는다

`synthesizer.judgment.json`이 있으면 `manifests/`에 정식 기록하고, 없으면 `runs/incomplete/`에 미완주 로그로 남긴다. 미완주 로그에는 파이프라인 순서대로 `roles_completed`·`roles_missing`·`last_role`을 기록해 어디서 멈췄는지 알 수 있게 한다.

**통계·대시보드·규칙 졸업 분석이 읽는 대상은 `manifests/`뿐이다.** `runs/incomplete/`는 진단용이며 집계에 섞지 않는다. (README "기록의 단일 원천" 절)

### 3. 중복 차단 — 해시 일치 기준의 마커

기록 후 `runs/current/.manifested`에 기록한 `outputs_hash`를 남기고, 같은 해시는 재기록하지 않는다.

마커를 **존재 여부가 아니라 해시 일치로 판정**하는 이유: 훅은 세션 턴마다 발동하므로, 파이프라인이 진행 중일 때 다른 세션의 훅이 마커를 남기면 정작 그 실행의 정식 매니페스트가 스킵될 수 있다. 해시로 비교하면 산출물이 늘어난 시점에는 반드시 기록된다. 실제로 이번 수정은 회귀 배치가 백그라운드로 도는 중에 적용됐고, 이 설계가 아니었다면 진행 중이던 회차의 기록을 잃었을 것이다.

### 4. 해시 필드의 의미를 바로잡는다

- `input_hash` — 입력 데이터 **파일 내용**의 해시. evidence의 `source_location`에서 규범·판례·판단 파일 경로와 `expected.json`을 제외해 입력 파일만 추린 뒤, 내용 해시 목록을 정규화해 해싱한다. 같은 입력이면 판정 결과와 무관하게 같다.
- `input_files` — `input_hash` 산출에 포함된 파일 목록 (감사용).
- `outputs_hash` — 판정 결과의 해시. 종전 `input_hash`가 담던 값.
- `escalation_reason` — synthesizer 판단 파일의 실제 `escalation_reason`.

재현성 대조는 `input_hash`가 같은 매니페스트끼리 한다. 단 **결론 수준 재현성은 `outputs[*].verdict`·`escalate`로 비교하고, `outputs_hash`로 판정하지 않는다.** `outputs_hash`는 `evidence_count`까지 포함하므로 결론이 같아도 거의 항상 달라진다 — 2026-08-01 재측정에서 5회 모두 `approve`였지만 `outputs_hash`는 5회 전부 달랐다. `outputs_hash`의 용도는 산출물 완전 동일성 확인(중복 기록 차단 등)이다.

후속 과제: 결론 수준 비교를 매니페스트만으로 하려면 `{역할: (verdict, escalate)}`만 해싱한 `verdicts_hash` 필드가 필요하다. 이번에는 추가하지 않았다 (회귀 통과 후의 추가 규범 변경이 되므로).

## 결과

- `.claude/hooks/write_manifest.py` 수정, `normative/schemas/manifest.schema.json`에 신규 필드 명세 추가.
- 훅 단독 테스트 4종 통과: 미완주 → `runs/incomplete/` 기록·`manifests/` 무변동, 미완주 재발동 시 중복 없음, 완주 후 2회 연속 발동 시 매니페스트 1건, 같은 입력·다른 판정에서 `input_hash` 동일·`outputs_hash` 상이.
### 5. `runs/current/` 정리 시점 — 현행 유지 (실행 시작 시에만 비움)

회귀 하네스가 실행 **종료 후에도** `runs/current/`를 비우게 할지는 미결이었다. **현행 유지로 확정한다** (2026-08-01, 저장소 소유자). 사유: 실행 직후 산출물을 사람이 그대로 들여다볼 수 있다는 가치가 크고, 중복 기록은 `.manifested` 마커가 이미 막고 있어 정리의 실익이 없다.

### 6. `verdicts_hash` 추가 — 승인하되 다음 사이클로 미룸

결론 수준 비교를 매니페스트만으로 하려면 `{역할: (verdict, escalate)}`만 해싱한 `verdicts_hash` 필드가 필요하다. **추가를 승인하되 이번에는 넣지 않는다** (2026-08-01, 저장소 소유자). 사유: 회귀를 막 통과한 안정 상태를 단건 개선으로 다시 여는 것보다, 다음 규범/코드 변경 사이클에 묶어 같은 회귀 게이트를 한 번 통과시키는 편이 낫다.
